# kbx v0.1.5

## `kbx suggest` shares its budget between generators

A run keeps at most 2,000 candidates, or the number `--budget` sets, as before.
Now each generator that found something is sure of an equal share of them, so one
generator can no longer fill the whole queue. A share a generator doesn't use goes to the best pairs left.
A pair found by two generators takes one place and counts for both.

The summary now has a row per generator, with what it found and what it kept:

```
13 candidates
  generator             found    kept
  schema_gap                0       0
  alias_cooccur             2       2
  common_neighbors          6       6
  ...
dropped 0 linked or rejected, 0 over budget
```

`alias_cooccur` scores a pair by how telling its shared terms are. A rare term
counts for more than a common one, and a term of several words for more than a
single word. One term makes at most 50 pairs, from the notes that use it most.

## Before you upgrade

- **`alias_cooccur` scores are on a new scale.** A 0.1.4 score is often higher
  than the best new one. A `kbx suggest` run in which `alias_cooccur` runs scores
  again the pairs it keeps, and takes out the stored 0.1.4 `alias_cooccur` pairs
  it doesn't keep. A pair taken out comes back on the new scale when a run finds
  and keeps it again.
  - A run narrowed by `--note` only takes out pairs at that note. A run whose
    `--generators` leaves out `alias_cooccur`, or in which it fails, takes out
    none.
  - A 0.1.4 pair with a judge verdict, a review such as a deferral, or an
    acceptance held in `.kbx/` is not taken out. It keeps its old score until a
    run finds it again, so it can still rank above new pairs in the queue.
- **`kbx suggest` no longer always waits for embedding.** It defaults to
  `--embed auto`: it embeds what has no vector yet if that should take 15 minutes
  or less, and otherwise goes on without it and says so. Set
  `KBX_EMBED_AUTO_MINUTES` to change the 15. `--embed wait` always embeds first,
  as 0.1.4 did, and `--embed skip` never does. Notes with no vector can still be
  found by keyword. Each run prints how many have vectors.
- **The first `kbx index` rebuilds the index once.** It picks up partial-path
  links that way: a link like `[[people/ann]]` now reaches
  `companies/acme/people/ann.md` when that is the one note whose path ends that
  way. No `--full` is needed. The rebuild keeps your reviews, accepted relations
  and candidates. It reads every note again, so on a large vault this first run
  takes as long as `kbx index --full`.
- **`kbx init` and `kbx doctor --fix` remove left-over qmd collections.** In the
  vault's own qmd index, a collection `kbx.toml` doesn't name is now removed, for
  example one from a config that has since moved. `kbx doctor` names them. A shared
  index named in `qmd.index` is never touched.
- **`kbx doctor --fix` can exit 1.** It does when a fix fails, such as a qmd
  collection it can't add or remove. Check any script that runs it. Plain
  `kbx doctor` still only warns.
- **`include` brings back notes that `.gitignore` excludes.** Add it to
  `.kbx/kbx.toml`, beside `exclude`, with `.gitignore` patterns from the vault root:

  ```toml
  include = ["/personal/"]
  ```

  It can't override `exclude` or a hidden folder. `kbx init` and `kbx doctor` now
  name each top-level folder whose markdown is all left out, say why and how many
  of those files git tracks, and give the `include` line that brings them back. A
  file git tracks inside an ignored folder is still left out until `include` says
  otherwise.
- **The built-in search engine downloads a 134 MB model on first use,** into your
  user cache: `~/Library/Caches/kbx/models/` on macOS, `~/.cache/kbx/models/` on
  Linux and `%LOCALAPPDATA%\kbx\models\` on Windows.
- **That model reads English only.** For notes in other languages, use
  `kbx init --search qmd`.
- **QMD is an option, not the default.** New vaults use the built-in engine. A
  vault whose `kbx.toml` says `search = "qmd"` stays on QMD.
- **`kbx suggest` defaults to `--judge auto`, which can spend money or plan
  quota.** It sends excerpts of your notes to the logged-in `claude` or `codex`
  CLI, or failing those to local `ollama` or `llama-server`. Use `--judge none` to
  stop at the candidates, or `--budget-usd` to cap a run.
- **Building from source.** CI and the release builds now use Rust 1.100.0, set in
  `rust-toolchain.toml`, so the npm binaries are built with it. That file is not
  in the crates, so `cargo install kbx` builds with your own Rust, as before. The
  crates set no minimum Rust version.

## Pull requests

  `alias_cooccur` pairs it didn't keep out of the queue, except ones with a
  verdict, a review or an acceptance held in `.kbx/`.

  so partial-path links are picked up without `--full`.

  each found and kept, and `alias_cooccur` scores rare and longer terms higher,
  with at most 50 pairs per term.

  now 1.100.0, and a weekly job tries the latest stable.
- #50: `kbx doctor` has a `write` row for the frontmatter setting, the `search`

  even in an ontology that doesn't declare it.

  excluded, with how many of those files git tracks and the `include` line to read
  them.
- #48: `kbx init` and `kbx doctor --fix` remove collections in the vault's own qmd
  index that `kbx.toml` doesn't name, and `kbx doctor` warns about them.
- #47: A build fix for clippy on Rust 1.100. Nothing changes for users.
- #46: `kbx suggest --embed auto|wait|skip` says how long embedding would take, and
  by default goes on without it when that is over 15 minutes.
- #45: qmd masks stay under qmd's length limit, a failed collection no longer
  takes the old one with it, and `kbx doctor --fix` exits 1 when a fix fails.

  note whose path ends that way. When several match, `link.unresolved` says how
  many.
- #43: `kbx watch` no longer indexes in the middle of a burst of saves when a save
  lands as it checks the files.
- #42: `docs/e2e-hq.md` records the second end-to-end run on a real vault, of
  v0.1.4.
- #41: `include` in `.kbx/kbx.toml` brings back notes that `.gitignore` excludes,
  and `kbx doctor` counts what `.gitignore` removes and `include` brings back.
- #40: The npm smoke checks wait for each platform package to reach the registry.
  Nothing changes for users.
